# Das Positioning-Deck — 6-Slide-Struktur

Quelle: Fletch / Anthony Pierri — "The only positioning deck you'll ever need"

## Übersicht

Ein starkes Positioning-Deck hat genau 6 Slides. Nicht mehr, nicht weniger. Es verwendet verschiedene "Anker", um die Positionierung zu verankern:

- **Category Anchor** (lila) — Die Produktkategorie, in der du positioniert bist
- **Use Case Anchor** (orange) — Die Aufgabe oder Initiative, die der Kunde ausführt
- **Alternative Anchor** (rosa) — Gegen wen/was du dich positionierst
- **Persona Anchor** (grün) — Die spezifische Zielgruppe
- **Company Anchor** (gelb) — Die Unternehmensgröße/-art der Zielgruppe
- **Problem** (rot) — Das Problem, das du löst
- **Value** (türkis) — Der Wert, den du lieferst

---

## Slide 1: Functional Description

**Zweck**: In einem Satz erklären, WAS ihr seid, FÜR WEN, und WAS ihr tut.

**Formel**:
```
[Name] ist ein/e [Category Anchor] {optional: [Alternative Anchor]},
die/der [Persona Anchor] in [Company Anchor] hilft, [Use Case Anchor].
```

**Beispiel** (Website-Agentur Oratory.co):
"Oratory.co ist eine **Website-Design-Agentur** [Category], die **Marketern** [Persona] in **Early-Stage B2B-Software-Startups** [Company] hilft, **ihre Brand zu erneuern und eine neue Website zu erstellen** [Use Case]."

**Wichtig**:
- Wähle bewusst deinen primären Referenzpunkt (Kategorie, Use Case, oder Alternative)
- Füge Segmentierung hinzu (Company-Typ, Persona), um die Positionierung zu schärfen
- Dieser Satz muss so klar sein, dass ein Fremder sofort versteht, was das Unternehmen tut

---

## Slide 2: Problem Framing

**Zweck**: Das Problem benennen, das ihr löst — verknüpft mit einem eurer Referenzpunkte.

**Formel**:
```
[Alternative/Kategorie-basiertes Problem] — verknüpft mit einem Referenzpunkt
```

**Beispiel**:
"Andere **Website-Design-Agenturen** [Category Anchor] **gehen über das hinaus, was ein Early-Stage-Startup in Bezug auf Prozess, Preis und Deliverables braucht** [Problem]."

**Wichtig**:
- Das Problem muss an einen deiner Referenzpunkte geknüpft sein (nicht frei schwebend)
- Es muss ein Problem sein, das jemand im Zielunternehmen besitzt und fühlt
- Spezifisch sein — "Der Markt ist ineffizient" ist zu vage

---

## Slide 3: Value Framing

**Zweck**: Zusammenfassen, wie ihr das Problem löst. Das ist eure Kernbotschaft.

**Formel**:
```
[Name] ist ein/e [Category Anchor],
[Value — wie ihr das Problem von Slide 2 löst].
```

**Beispiel**:
"Oratory ist eine **Website-Design-Agentur** [Category], die **von Grund auf darauf ausgelegt ist, die spezifischen Bedürfnisse eines Early-Stage-Startups zu erfüllen — ohne den Ballast von Agenturen, die auf größere Unternehmen fokussiert sind** [Value]."

**Wichtig**:
- Das Value Framing muss direkt auf das Problem von Slide 2 antworten
- Es soll die Differenzierung zusammenfassen, nicht einzelne Features auflisten
- Einfach genug, dass man es in 10 Sekunden versteht

---

## Slides 4-6: Supporting Arguments (3 Stück)

**Zweck**: Jeder Supporting Argument liefert einen konkreten Beleg für die Value-Behauptung aus Slide 3.

### Struktur pro Supporting Argument:

```
**[Argument-Headline]** (kurzer, einprägsamer Titel)

[Erklärender Text — 2-3 Sätze, die das Argument ausführen,
typischerweise im Kontrast zur Alternative positioniert]

**Features/Belege:**
- [Konkretes Feature oder Fakt, der das Argument glaubwürdig macht]
- [Weiteres Feature oder Fakt]
```

### Beispiel (Oratory.co):

**Supporting Argument 1: Leichtgewichtiger Prozess**
"Im Gegensatz zu anderen Agenturen, die auf lange Timelines, geschichtete Teams und aufwändige Discovery-Phasen setzen, arbeitet Oratory in schnellen Sprints mit Fokus darauf, die Kernbotschaft in 4 Wochen live zu bringen."
- Features: Fast Sprints, 4 Week Go-Live

**Supporting Argument 2: Startup-gerechtes Pricing**
"Statt eines 6-stelligen Budgets für ein komplettes Rebranding bietet Oratory Pakete, die auf das Budget und die Geschwindigkeit von Early-Stage-Startups zugeschnitten sind."
- Features: Fixed-Price Pakete, Kein Discovery-Overhead

**Supporting Argument 3: Positioning-First Approach**
"Oratory startet nicht mit Design, sondern mit der Positionierung. Dadurch entsteht eine Website, die nicht nur gut aussieht, sondern die richtige Botschaft an die richtige Zielgruppe kommuniziert."
- Features: Positioning Workshop inklusive, Messaging-Framework vor Design

### Wichtig für Supporting Arguments:
- Jedes Argument braucht einen klaren, einprägsamen Titel
- Die Argumente müssen durch Features/Fakten untermauert sein — sonst sind es nur Behauptungen
- Idealerweise sind die Features schwer kopierbar oder einzigartig
- Die drei Arguments zusammen sollten die Hauptbotschaft aus Slide 3 vollständig stützen

---

## Output-Format

Erstelle das Positioning-Deck als strukturiertes Markdown-Dokument:

```markdown
# Positioning-Deck: [Unternehmensname]

## 1. Functional Description
[Vollständiger Satz mit allen Ankern markiert]

## 2. Problem Framing
[Problem verknüpft mit Referenzpunkt]

## 3. Value Framing
[Kernbotschaft — wie ihr das Problem löst]

## 4. Supporting Argument 1: [Headline]
[Text]
**Belege:** [Features/Fakten]

## 5. Supporting Argument 2: [Headline]
[Text]
**Belege:** [Features/Fakten]

## 6. Supporting Argument 3: [Headline]
[Text]
**Belege:** [Features/Fakten]

---

## Ergänzende Elemente (nicht im Deck, aber wichtig für Umsetzung)

### Positioning Map
[JTBD, Alternativen, Probleme, Differenzierung — als Tabelle]

### ICP Summary
[Kernmerkmale des Ideal Customer Profile]

### Messaging nach Awareness-Stufen
[Zusammenfassung der Messages für Out-of-Market, In-Market, Shopping]
```
